# ejabberd container for the UT4 smoke stack

Custom ejabberd image. Sits in front of the master server and handles
XMPP auth via the `extauth/yesman.py` script that validates session
tokens against `/account/api/oauth/verify`.

## Build

```bash
cd XMPP-ejabberd
docker build -t ut4ms-smoke-xmpp:local .
```

## Layout

- `Dockerfile` — adds python3 to `ejabberd/ecs:latest`
- `conf/ejabberd.yml` — bind on 0.0.0.0:5222, extauth via `/extauth/yesman.py`
- `extauth/yesman.py` — speaks ejabberd's length-prefixed extauth protocol;
  validates against the master server's `/account/api/oauth/verify`

## Runtime requirements

The compose run-time needs to bind-mount or pre-place:
- `conf/ejabberd.yml`     → `/home/ejabberd/conf/ejabberd.yml`
- `extauth/yesman.py`     → `/extauth/yesman.py`
- `tls/fullchain.pem`     → `/tls/fullchain.pem` (generate per-deploy, see below)
- `database/`             → `/home/ejabberd/database/` (persistent ejabberd state)

## Generating tls/fullchain.pem

ejabberd needs a single PEM with cert + key concatenated. On the dev
box this is generated by `nix-config`'s `ut4-redirect` module via openssl;
on a non-NixOS deploy, run:

```bash
openssl req -x509 -newkey rsa:2048 -nodes -days 3650 \
  -subj "/CN=ut4.pick.haus/O=ut4-redirect" \
  -addext "subjectAltName=DNS:ut4.pick.haus,DNS:prod.ol.epicgames.com,DNS:friends-public-service-prod06.ol.epicgames.com" \
  -keyout key.pem -out cert.pem
cat cert.pem key.pem > tls/fullchain.pem
```
